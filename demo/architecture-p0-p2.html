AI 面试 Agent · 架构（P0–P2）
核心手写 + 外围组件 · LLM = DeepSeek（OpenAI 兼容接口）· 每层只依赖下一层
①入口层 · 只做参数解析与错误翻译
app/main.py · CLI
五个子命令：demo / chat / prep / ask / interview。统一把 402（余额不足）翻译成人话，不让堆栈直接糊脸。
↓
②编排层 · 两个「循环」
app/agent.py · ReAct 循环1–8 次
手写 while：messages 发给模型 → 有 tool_calls 就逐个执行 → 结果以 role=tool 回喂 → 直到模型不再调工具。max_iter=8 兜底。
app/interview.py · 面试状态机N+1 次
模式 A 一问一答：出题 → 收回答 → 打分 → 入库 → 下一题；低分题可选追问；结束一次性出复盘报告。
↓
③能力层 · 每个文件一件可复用的事
app/tools.py
@tool 注册表 + tool_schemas() 自动生成 OpenAI function-calling schema；内置 next_question / save_feedback。
app/prep.py1 次
JD + 简历 → 题库 JSON（id / category / topic / question / points / followups）。
app/scoring.py每答 1 次
六维 rubric；加权总分由代码重算，模型给的 total 一律丢弃，越界 clamp 到 0–5。
app/report.py
三种 Markdown 渲染：题库清单 / 单题评分卡 / 整场报告（总览 + 复习优先级 + 逐题改进话术）。
↓
④基础设施层 · 所有对外副作用的收口
app/budget.py · 预算护栏
包在 LLM 最外层：调用前判上限、打印 [LLM 调用 i/max]、超限抛 BudgetExceeded，让上层降级而不是继续烧。
app/llm.py
RealLLM（openai SDK + base_url）与 StubLLM（无 key 的确定性假模型，用来跑通循环）。
app/session.py
SQLite：sessions（一场面试）+ turns（每题评分与依据），为 P3 的跨会话记忆留了地。
app/jsonutil.py · app/prompts.py
JSON 稳健抽取（剥围栏、忽略前后解释文字）；四段式 system prompt（角色 / 边界 / 决策权 / 输出约束）。
↓
⑤输出层 · 都是人能直接打开的文件
bank.md题库，Markor 可读
bank.json结构化，喂给 interview
scorecard.md单题六维评分卡
interview.db会话与回合

一场面试的时序（模式 A）· 循环结构

每题循环 · 重复 N 次（N = 题库题数）
出题→你回答→打分（1 次）→写 turns（入库）→还有下一题？
← 是：回到「出题」，进入下一题（i = i + 1）
← 低分且开启追问：追问（+1 次）→ 回到「打分」，再入库一次
← 空回答：跳过本题，不计分、不占调用
否（题答完，跳出循环）→复盘报告（1 次）→report.md
「写 turns」不是对话轮次，而是往 SQLite 的 turns 表插一行：题目 / 你的回答 / 六维分 / 加权总分 / 引用依据。循环用 for q in questions 实现，不是递归。

调用预算（这次真的会花钱的地方）

命令每次峰值调用
prep 生成题库1 次
ask 单题打分1 次
chat 循环1–8 次
interview 整场题数 + 1
interview + 追问2×题数 + 1（最坏）

看代码时只盯这三个设计

1. 确定性在外：总分、排序、降级全由代码算，模型只给「分数 + 依据」。
2. 判断在内：模型的自由度被 prompt 的四段式（角色 / 边界 / 决策权 / 输出约束）圈住。
3. 护栏在最外：BudgetedLLM 包住一切调用，成本失控在结构上不可能发生。
